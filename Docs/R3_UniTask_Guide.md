## 3. 핵심 기술 스택 활용 전략 및 구조 설계안

- 기획의 의도를 프로그래밍 아키텍처로 번역하는 가이드라인
- 시스템의 결합도를 낮추고 유지보수성을 높이기 위해 객체 지향 프로그래밍(OOP) 관점과 디자인 패턴(Factory, Builder, MVVM)을 결합하여 기술

### 3.1. UniTask 활용 전략: 인력 관리 - 캐릭터 생성 (데이터 생성)

**[개요]**
- `StaffBuilder`에서 직원을 생성하는 과정은 스탯 산정 -> 초기 데이터(`StaffInitData`) 생성 -> 에셋 로드 -> 엔티티(`StaffEntity`) 빌드 및 생성"이라는 순차적인 절차를 가짐
- 이 과정에서 메인 스레드(게임의 프레임)가 멈추지 않고 부드럽게 진행되도록 `UniTask`를 활용한 비동기(Asynchronous) 처리 도입

**[객체 지향적 설계 전략]**
* **역할 분리 (SRP):** 랜덤 데이터 계산은 팩토리(Factory)가, 객체의 조립은 빌더(Builder)가 담당
* **비동기 흐름 제어:** 외부의 데이터베이스(혹은 JSON)에서 직업별 가중치 테이블을 읽어오거나, 직원의 프리팹 / 이미지 에셋을 메모리에 올리는 작업은 시간이 걸리므로 `UniTask`를 반환하는 비동기 함수로 설계

**[클래스 및 인터페이스 구조안 예시(수정 가능)]**

1.  **`IStaffFactory` (인터페이스)**
    * **역할:** 복잡한 기획적 확률 연산을 캡슐화하여, 외부에서는 그저 "직원을 만들어달라"고 요청만 할 수 있음
    * **핵심 함수:** `CreateInitDataAsync()` -> `UniTask<StaffInitData>`를 반환 (내부적으로 이름 DB를 읽거나 스탯을 랜덤하게 굴리는 시간을 비동기로 대기)
2.  **`StaffBuilder` (클래스)**
    * **역할:** 팩토리에서 만든 순수 데이터(`StaffInitData`)를 바탕으로 실제 유니티 씬에 존재하는 오브젝트(`StaffEntity`)를 조립
    * **핵심 함수:** `BuildStaffEntityAsync(StaffInitData data)` -> 아바타 에셋(Addressables 등)을 비동기로 로드하고, 컴포넌트를 부착한 뒤 `UniTask<StaffEntity>`를 반환
3.  **`StaffRecruitManager` (시스템 클래스)**
    * **역할:** 유저가 '고용 버튼'을 눌렀을 때 전체 흐름을 관장
    * **흐름:**
        > - 유저 클릭 -> "화면 로딩 UI 켜기" -> 팩토리에게 `CreateInitDataAsync` 요청 대기 -> 완료되면 빌더에게 `BuildStaffEntityAsync` 요청 대기 -> 완료되면 "화면 로딩 UI 끄기" 및 씬에 캐릭터 등장 (이 흐름이 `UniTask` 덕분에 콜백 함수의 연속적 중첩(콜백 지옥)이 없어짐)

### 3.2. R3 활용 전략: 경제 시스템 - 재화 구분 (돈)

**[개요]**
- 게임 내 재화(돈)는 스태프 고용(`Hire_Cost`), 월급 지출(`Salary`), 게임 출시 수익 등 다양한 원인에 의해 끊임없이 변동
- R3는 이러한 '상태의 변화'를 구독(Subscribe)하고 있는 여러 UI나 시스템에 즉각적이고 안전하게 전파하는 데(Reactive Programming) 최적화

**[객체 지향적 설계 전략]**
* **데이터와 뷰의 분리 (MVVM 패턴 유사):** 돈의 실제 데이터를 관리하는 클래스와, 화면에 돈 수치를 텍스트로 보여주는 UI 클래스를 완전히 분리
* **접근 권한 제어 (캡슐화):** 돈을 함부로 수정하지 못하게 인터페이스를 분리, 읽기(구독) 전용 인터페이스와 수정 기능을 분리하여 안전성 높임

**[클래스 및 인터페이스 구조안 예시(수정 가능)]**

1.  **`IEconomyReadService` (읽기/구독 전용 인터페이스)**
    * **역할:** UI나 타 시스템이 현재 돈의 상태를 관찰할 수만 있게
    * **핵심 프로퍼티:** `ReadOnlyReactiveProperty<long> CurrentMoney` (R3 제공 타입)
2.  **`IEconomyWriteService` (쓰기 전용 인터페이스)**
    * **역할:** 인게임 로직(월급 지급, 수익 발생)에서 돈을 증감시킬 때 사용
    * **핵심 함수:** `AddMoney(long amount)`, `SpendMoney(long amount)` (일반 함수)
3.  **`EconomyManager` (구현 클래스)**
    * 위 두 인터페이스를 모두 상속받음 내부에 실제 값인 `ReactiveProperty<long> _currentMoney`를 가지고 있음
    * `SpendMoney` 함수가 호출되어 `_currentMoney`의 값이 변하면, R3 로직에 의해 이 값을 구독하고 있는 모든 객체에 자동으로 알림이 감
4.  **`TopBarMoneyUI` / `StaffHireUI` (UI 제어 클래스)**
    * **역할:** 화면의 텍스트 컴포넌트를 관리
    * **흐름:**
        > - UI 클래스들은 게임 시작 시 `IEconomyReadService.CurrentMoney`를 **'구독(Subscribe)'**
        > - 이후 다른 스크립트(예: 급여 시스템)에서 `SpendMoney`를 호출해 돈이 깎이면, UI 스크립트는 Update(매 프레임 확인)할 필요 없이 '돈이 변했다'는 신호를 R3로부터 받아 즉시 화면의 텍스트를 최신화 (최적화와 코드 복잡화 방지)
