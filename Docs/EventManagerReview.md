# Develop 브랜치 기준

## 파악한 것들
### EventManager
- 기존 코드에서는 스크립트 따로 내부에서 id값으로 중복 관리를 각 이벤트종류마다 따로했지만 이벤트매니저에서 한번에 중복관리를함.
- 구글시트 데이터를 이벤트 매니저에서 관리(외부가 아닌 내부에서).
- TaskSo는 데이터 저장만 담당.
- 각 스크립트는 이벤트 실행을 담당.
- 스크립트로 관리하면 데이터는 씬전환시 날아갈수 있음, SO는 안날아감 다시 로드 안해도됨.
- _wasDownload는 중복다운로드 방지.
- 랜덤 발생 runIds에 없는 id값이 나올때까지 이벤트 뽑기. 있는 id값이면 다시 뽑고 없는 값이면 반환.
- 써도 되는 id값이 나오면 데이터 적용.
- runIds초기화는 rel/v0.1.1브랜치에 있음.
- EventDataStruct로 묶어서 한번에 데이터 관리
- 프로젝트가 끝나면 Reset으로 모든 타입들의 runIds를 초기화 시키면서 모든 이벤트가 다시 나올수 있게 만듬.
- 랜덤 발생하고난뒤에 ui에 보여질 데이터를 지정 그리고 실행.
- ```if (!Utils.Environment.isDevelopment) return;``` 개발부분에서만 다운로드 하게 하고 미리 다운받고 빌드에서는 저장된 데이터를 사용하게끔 사용.

### EventDataLoader
- 기존에는 런타임메모리에 딕셔너리로 저장했는데 현재는 본인이 들고있지 않고 외부에서 SO를 외부에서 주입받아서 주입받은 SO에 데이터를 넣어주는 역할.
- 중복 방지를 위해 Clear먼저 해준다.
- 딕셔너리에 바로 넣지 않고 EventTaskData로 바꿔서 저장. 랜덤으로 뽑아서 ui에 보여줄 데이터
- SO의 리스트로 바로 저장.
- 각 이벤트들의 Task에 바로 저장시켜둬서 분리와 데이터 저장을 동시에 진행.
